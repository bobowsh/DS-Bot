## Windows cua：两套解法怎么选

我们的解法：`@trycua` 整个 scope 不进 asar，由 `extraResources` 落到 `resources/node_modules/@trycua`，让 Node 的 `node_modules` 向上查找命中真实路径，`dlopen` 直接成功。

上游的解法：要在合并时读 `@trycua` 相关提交与 `electron-builder.yml` 的差异才能判断。

**判断标准**（按优先级）：
1. 上游是否彻底解决了同一个 `dlopen` 路径问题；
2. 上游方案是否不依赖 `extraResources`（更少定制更好维护）；
3. 若上游方案成立，**换成上游的**，删掉我们的 `extraResources` 条目与注释，减少分叉面。

**拿不准就保留我们的**，并在 PR 里如实写明「上游方案未采用，原因 X」。
