# 让 CI 在干净环境里真正跑通

Refs #66

- 日期：2026-11-15
- 状态：**已与用户对齐，实施中**

## 一、要解决什么

GitHub Actions 上 14 个检查项里 **11 个失败、2 个通过、1 个跳过**，而且**基线（我们改动之前）就是这样**：合并前后失败集合逐条相同。CI 从没绿过，起不到拦截作用。

目标：**CI 在 GitHub 的干净机器上真能跑通**，不靠本机任何资源。

## 二、纠正一个前提

CI 跑在 GitHub 的干净机器上，本机有什么对它没有影响。不可能靠改本地资源让 CI 过。正确方向是反过来：**让代码不再依赖仓库外的任何东西**。

## 三、四类失败（均已查日志）

### 1. npm ci 失败 → 5 个 job

根因不是 peer 冲突本身，是 app 自己的插件依赖版本落后于出厂清单：

| 包 | app/package.json 原值 | 出厂清单 |
|---|---|---|
| dsh-chat-import | 0.26.3 | 0.26.6 |
| dsh-xdpool | 2.6.1 | 2.6.7 |

CI 日志显示它解析到 dsh-chat-import@0.26.3（旧版），而 overrides 按新版配置，版本对不上于是 ERESOLVE（schemastery peer 冲突）。

### 2. workflow 里产品名还是 LinkBot → 4 个打包 job

实测 29 处命中：23 处要改、6 处必须保留。

必须保留的 6 处：DisplayName -like LinkBot* 四处（查找旧版本安装以便升级），以及 APPDATA/LinkBot 与 .ds-bot（旧 userData 目录，见 app/src/legacy.mjs 的 LEGACY_USER_DATA_NAMES）。

真实名字以配置为准：productName=LinkHarness、artifactName=LinkHarness-version-os-arch、executableName=linkharness、desktopName=dsbot.desktop。

### 3. 测试读仓库外的本地目录 → 4 个 test job

ds-bot/test/aide-icon.test.js 从仓库外两层读 dsh-plugins-dev/dsh-aide/icon.svg。

用户拍板：把图标副本签进仓库（729 字节）。放 ds-bot/test/data/aide-icon.svg，测试从仓库内读，三条断言一条不动。不删测试、不 skip。

### 4. Leak scan 吞了错误

scripts/scan.mjs 的 walk(root) 在目录不存在时抛裸 ENOENT，日志里只剩 exit code。先只做一件事：让它把真实错误打出来。

## 四、一个实测否定：npm ci 不支持 --legacy-peer-deps

最初想加 --legacy-peer-deps。实测该参数只对 npm install 有效，npm ci 加上直接报 npm error。

npm ci 接受的是 --force，实测通过：added 1148 packages。

## 五、验收标准

1. 两个插件版本 = 出厂清单值，lock 同步
2. 本机 npm ci --force 通过，无 ERESOLVE
3. aide-icon.test.js 三条全过，不读仓库外路径
4. node scripts/scan.mjs 缺目录时打出路径与原因，退出码 2
5. workflow 里剩余 LinkBot 全是旧目录/旧显示名兼容逻辑
6. 两侧门禁与基线对比不新增失败

BLOCKED：无法在本地复现 GitHub 干净环境，「改完 CI 真能过」只能推到 PR 上等实跑，不许写已修复。

## 六、不做的事

- 不动 .github/workflows/release.yml
- 不用 skip / continue-on-error 糊弄
- 不删测试、不改断言来凑绿
- 不改旧目录兼容逻辑
